A core with no noise: the silent cell

MakhOS engineering · MakhOS 2.0 (SMP) · commercial edition

The fuzz cell gives one CPU to the kernel's own fuzzer. It is built on a simpler, more general idea — the silent cell: one CPU taken out of the scheduler so a single workload can run on it with nothing else interfering. No other thread, no timer tick, no inter-processor interrupt. A core with no noise.

On a normal OS, even a CPU "dedicated" to one task is interrupted constantly — the scheduler tick fires, other cores send it IPIs, a TLB shootdown stalls it mid-instruction. For most software that jitter is invisible. For a latency-sensitive loop — a matching engine, a packet pipeline, a real-time controller — it is the difference between a predictable tail and a long one. Linux addresses this with isolcpus and nohz_full bolted on. MakhOS builds it in.

What makes a CPU noisy — and how the cell removes it

Three sources of interference, three answers:

  • The timer tick — masked. The cell's local APIC timer is turned off while it is silent, so the scheduler never preempts it.
  • IPIs — refused. Reschedule and remote-call interrupts aimed at the cell are declined; the root never steals its attention.
  • TLB shootdowns — deferred. This is the subtle one.

The deferred flush

When the kernel changes a page mapping, every CPU must drop the stale entry from its TLB — normally by an IPI that interrupts each core and makes it flush. A silent cell cannot take that IPI without losing its silence. So the cell does not flush on demand: the change is recorded, and the cell applies it at an epoch gate — a point where it is already synchronizing — rather than mid-workload. Correctness is preserved (the cell never uses a stale mapping for memory it touches) without a single interruption. Pages the kernel wanted to reclaim are simply parked until the cell passes the gate; the cell's counters show exactly how many.

Driving it, and measuring it

A silent cell is one command away:

cell start              # take the last CPU out of the scheduler
cell                    # its counters: ticks, locks, IPIs refused, pages parked
cell ping e1 10000      # round-trip latency on a path, from the root
cell stop               # give the CPU back

The cell can also do real work and report its latency. Three paths are measured end to end: E1, a message that comes straight back on an in-kernel channel; E2, a frame sent out of a dedicated second NIC in loopback and back; and E3, a real ICMP echo to the gateway on the cell's own network. Each run reports the full distribution — min, p50, p90, p99, p99.9, max — not just an average, so the tail is visible.

One honest note on the numbers: today they are measured under QEMU-TCG, where the host's cores are multiplexed and timing is the emulator's, not real silicon. The percentiles prove the mechanism — the cell takes no tick, refuses its IPIs, parks its pages, and answers on every path — but absolute latency figures wait for bare-metal hardware. We report what we measured and label where we measured it; we do not dress an emulator up as a benchmark.

Where it goes: the application cell

The silent cell runs a fixed in-kernel workload today. The cell abstraction, though, takes a type — silent, fuzz — and the natural next type is an application cell: the same zero-noise core, handed a latency-sensitive user workload instead of a fixed one. A matching engine is the canonical case — busy-poll a dedicated NIC for market data, keep the order book in memory, match, and emit, all on a core the scheduler never touches and the shootdown never stalls. That is exactly the shape high-frequency systems build by hand with isolated cores and kernel-bypass networking; MakhOS already has the three ingredients — the isolated core, the dedicated NIC, and the lock-free channel back to the root. Wiring a pluggable payload onto them is the roadmap, not a claim made today.

The silent cell and the fuzz cell are two faces of one mechanism — a CPU partitioned out of the system for a single purpose, with the hard parts (interrupt silence, a correct deferred flush, a clean handshake back to the root) solved once. MakhOS 2.0 is available under commercial license.
